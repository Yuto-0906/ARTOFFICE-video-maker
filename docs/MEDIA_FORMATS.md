# 動画・サムネイルの形式対応

## パソコン版

動画入力：MP4，MKV，MOV，WebM，MTS，M2TS，AVI，WMV。
画像入力：JPEG，PNG，HEIC，HEIF，WebP，TIFF（.tif／.tiff），BMP，AVIF，GIF。
サムネイル出力：JPEGまたはPNG。GIFは先頭フレームを用いる。

ファイル選択，フォルダー読込，再リンク，ドラッグ＆ドロップで同じ対応形式を使う。標準プレーヤーで再生できない入力は，元動画を保持したまま表示位置の30秒分だけ再生用のMP4を作る。H.264映像とAAC音声は可能なら再圧縮せずに格納し直し，それ以外は再生用映像へ変換する。動画全体の変換を待たず，再生位置バーから任意の位置へ移動できる。不要になった準備処理は中止する。完成動画には元動画を使用する。再生用キャッシュは最終更新から7日以上経過したものを起動時に削除する。

既存プロジェクトでサムネイルの保存形式が未指定の場合はJPEGを使う。PNGを選ぶと，出力名・同名ファイルの上書き確認・一時ファイル・実際の画像エンコーダーをPNGへ揃える。

## iOS版

パソコン版と同じ入力形式に加え，従来のM4V入力も維持する。標準のAVFoundationが再生できる動画は従来どおり取り込む。再生できない動画は，固定リビジョンのFFmpegKitで互換MP4へ変換する。対応するH.264／HEVC映像は再圧縮せず格納し直し，必要に応じてVideoToolboxまたはMPEG-4 Part 2へ変換する。音声はAACへ揃える。変換前の動画情報は，動画ごとに独立したFFmpegの読み取りコンテキストを作って取得する。コマンド実行の出力や前回の実行状態には依存しない。

変換した動画は，元ファイルを変更せずイベント内へ保存する。「参照」指定でも，変換が必要な入力は端末内に保存される。変換前に空き容量と置換素材の長さを確認し，変換後の素材から再生・カット・出力する。変換が必要な動画では，追加の保存容量と処理時間が必要になる。

画像はImageIOで最初の画像を読み，必要に応じてFFmpegの先頭フレームデコードを使う。取り込んだ画像は追加の非可逆圧縮を避けてPNGで保存する。共有と動画書き出しに添付するサムネイルは，選択したJPEG／PNG形式を使用する。

## 出力の自動設定

新規プロジェクトでは，解像度とフレームレートを先頭の動画へ合わせる。並べ替えて先頭が変わると，出力設定も追従する。1本の完成動画へ結合するため，ほかの動画もこの共通設定へ揃える。1080p／1440pと標準フレームレートの手動選択も維持する。古い保存データで自動設定が未指定の場合は，保存済みの解像度を保ち，パソコン版のフレームレートは従来の60000/1001とする。iOS版の自動フレームレートは，既存の実装どおり対応する標準レートから選ぶ。

パソコン版は元動画の有理数フレームレートをフィルター・エンコーダー・出力検査へ渡す。VideoToolboxでのパケット長補正も選択レートへ合わせる。解像度の自動設定では，平均映像ビットレートを1080pの15Mbpsと画素数の比から求め，4～80Mbpsの範囲に収める。iOS版でも，実際に使う幅・高さ・ビットレートを描画・容量見積もり・再利用キャッシュの識別へ反映する。

## 検証

Windows：ビルド，フロントエンド21件，Clippy，Rust通常テスト21件が成功した。任意の実素材プレビュー計測も実行し，指定フォルダーの先頭MKV（1920×1080・30fps・約23分36秒）では冒頭30秒を0.382秒，600～630秒を0.374秒で準備した。計測はバックエンドのファイル準備時間である。配布用Windowsアプリでも確認し，キャッシュ未作成時の初回表示は約2.6秒，10分地点への移動は約1.8秒だった。区間をまたぐ連続再生と，複数回シーク後に最後の指定位置を表示することも確認した。各区間のキャッシュは約28MBと48MBで，元の約1.85GB全体を作り直していない。合成素材では，非キーフレーム位置から始まる区間の復号フレームが元動画と一致すること，元ファイルが変化しないこと，元の解像度・30fpsでの出力，旧形式の59.94fps既定値を確認した。既存の実素材全体やフル解像度の長い任意試験は未実行。

iOS：Azure Pipelinesのrun 47で形式対応がiPhone・iPadの両方で成功した。今回追加した自動解像度設定も[run 48](https://dev.azure.com/yuto200596/ios-development/_build/results?buildId=48)で成功した。Core 32件，実機用コンパイル，iPhone・iPad各8件を確認し，実際に元動画の幅・高さ・フレームレートで書き出す試験も両方で通った。iOS対象リビジョンは`7a955fc3d3ea526841788a8a73d7445bb1a14a69`。[run 49](https://dev.azure.com/yuto200596/ios-development/_build/results?buildId=49)で開発用署名も成功し，Windowsへの取得と構成検査を完了した。同梱8フレームワークの署名関連ファイル，埋め込みプロファイルと承認済み原本の一致を確認した。実機への導入は端末接続待ちであり，実機での機能確認は未実施。配布ファイルと再導入手順は[今回の配布記録](MEDIA_FORMATS_DELIVERY.md)に記録した。
