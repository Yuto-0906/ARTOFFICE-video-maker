# iPhone・iPadの操作改善

更新日：2026年10月27日。

状態：ソースの修正済み。Azure Run 1でCore25件とiOSアプリ・テストのコンパイルが通り，シミュレーター試験を実行中である。署名・実機導入は未実施。Codemagicの無料macOS枠は再確認時点でも501分／500分で，有料契約は有効にしていない。iPadの導入版は引き続き`f3aa9a8`の1.0（ビルド1）であり，以下の改善はまだ含まれない。修正版は1.1（ビルド2）として区別する。

その後のスキル再読込みを受け，無料枠が未消費だったAzure PipelinesへGitHubを接続し，署名なし検証を開始した。[Azureの設定状況](IOS_AZURE_PIPELINES.md)を参照する。署名情報の送信には自動承認レビューによる追加の確認待ちがある。

## 今回変更した操作

| 困っていた点 | 修正版の操作・挙動 |
|---|---|
| 動画を1本ずつ選ぶ必要がある | 「フォルダー内の動画をまとめて追加」と「動画をまとめて選択」を分けて表示する。フォルダー内は下位フォルダーも走査し，動画を順次取り込む。隠しファイル・パッケージ内・シンボリックリンクは対象外とする |
| トリミング中に音声が出ない | 再生時に`AVAudioSession`を`playback`・`moviePlayback`で有効化し，プレーヤーもミュート解除・音量1を明示する。実機で音が出ることは更新後に確認する |
| 再生と停止のボタンが別 | カット画面と仕上がりプレビューを「再生／一時停止」の1つのボタンにする。フレーム送りは残す |
| サムネイルの位置調整が直感的でない | 16:9の枠内の写真を直接ドラッグし，ピンチした位置を中心に拡大する。拡大率のスライダーとリセットも用意する。100％は枠を満たす最小サイズとし，切り取れる余地のない方向へは動かない。プレビューとJPEG出力で同じ切抜き計算を使う |
| Box・Google Driveの動画を使いたい | iOSの「ファイル」に表示される各提供元から選択する。ファイルの取得・コピーは`NSFileCoordinator`経由で行う。参照方式では選択したフォルダーのアクセス情報も保存する。提供元がフォルダー選択に対応しない場合は複数ファイル選択を使う |
| 使い終わったコピー・キャッシュが残る | 右上の「容量」から，現在使っていないコピー済み素材・処理用キャッシュ・アプリ内の完成品をそれぞれ確認して削除する。動画一覧から外す際も，コピーを残すか削除するか選べる。書き出し成功時には処理済み区間を現在と直前のジョブの2回分へ整理する |
| 取込み後に内容を見て名前と順番を整えたい | 各動画の「内容を確認・名前を変更」から再生，表示名・バンド名の編集，出演順の変更を行う。一覧の上下ボタン・ドラッグ・表示名の番号順ソートに対応し，連結した動画はバンド単位で移動する。連結内の順番も変更できる |
| 右上のチェックマークの意味が不明 | 「保存」の文字と自動保存の状態を表示し，手動保存が成功したら「保存しました」を次の編集まで残す。失敗時はエラーを表示する |

表示名の変更はアプリ内のプロジェクトに保存する。元のファイルやクラウド上の名前を変更せず，元の名前も画面に表示する。表示名からバンド名を取り出す操作は明示的なボタンにし，名前の整理だけで動画タイトルを意図せず変更しないようにする。番号順ソートには`01_バンド名`などの表示名を使える。

Box・Google Driveの利用には，各アプリへサインインし，「ファイル」の場所で有効にしておく必要がある。クラウド・提供元ごとのフォルダー選択，複数選択，オフライン取得，再起動後の参照可否は未確認である。基本は端末内コピーを使い，参照が復旧できない場合は素材を選び直す。サービス固有のOAuthやアプリからの外部ファイル削除は追加しない。

## 容量整理と長い動画の扱い

コピー済み素材は，現在の動画・サムネイルが参照していないものだけを削除候補にする。素材削除の前に復旧用の保存世代も現在の編集内容へそろえ，復旧後に削除済み素材を参照することを避ける。複製プロジェクトのハードリンクは別の参照として残る。削除対象をアプリ管理下へ限定し，シンボリックリンクによる外部への転送を検査する。

処理済み区間の自動整理では，確定した完成動画・チャプター・JPEGと入力素材を残す。失敗・中止した書き出しでは確定済み区間を維持する。次にプロジェクトを開くときは，書込み途中の区間・内部保存先の未完成MP4を整理する。完成品とコピー済み素材はユーザーが削除するまで保持し，処理用キャッシュとは区別して容量を表示する。複数ジョブ間で同じ実体へハードリンクした区間は，容量表示で重複計上しない。

フォルダーの全動画を同時にデコードせず，1ファイルずつ情報を取得・コピー・保存する。動画全体を`Data`へ読み込まず，既存の区間出力・再利用・端末別バッファ制御を維持する。サムネイル共有の一時JPEGは共有終了時に削除し，残っていた同専用領域の古いJPEGも整理する。5時間の実素材試験は，従来のユーザー指示どおり必須に戻さない。

## 検証状況と再開手順

Windows上では差分書式と`bash -n scripts/ios/ci.sh`の確認を実施した。Swiftのツールチェーンはこの環境になく，ソースの目視確認やシェル構文の確認をSwiftコンパイル成功とは扱わない。

Core試験には，連結を保つ並べ替え，表示名の保存，既存JSONの読込み，100％の写真の移動制限，ピンチの中心保持，未使用素材の削除と復旧用世代，別プロジェクトのリンク保持，キャッシュ整理と完成品保護を追加し，Azure Run 1の25件に含めて通過した。iOS試験には，フォルダー走査，音声付き素材の再生設定と切替，写真を動かした後のJPEGの画素を確認する試験を追加した。UI試験にはフォルダー・複数選択ボタンと保存完了表示の確認を追加した。**iOS側の試験結果はまだ確定していない。**

1. Codemagicの実行枠を確保したら，対象リビジョンの`ios-check`でCore・アプリとテストのコンパイル・iPhoneとiPadの試験を実行する。止まった操作は既存の`ARTOFFICE UI`ログから特定する。
2. 通過したリビジョンを`ios-device`で署名し，IPAのバージョン・Bundle ID・リビジョン・プロファイルを照合する。既存の編集情報を保持したままiPadへ上書きする。
3. 短い動画を2～3本入れたフォルダーで，一括取込み，内容確認，表示名変更，並べ替え，保存再開を確認する。連結内の移動も確認する。
4. 消音モードも含めてカット画面の音声と再生／一時停止を確認する。末尾からの再開，画面を閉じた後の停止も確認する。
5. 横・縦の写真でドラッグ・ピンチ・リセットを試し，JPEG単独保存と動画出力時のJPEGが画面内の切抜きと一致することを確認する。
6. Box・Google Driveをそれぞれ実際に選び，コピー後の再起動・オフライン再開を確認する。参照方式は提供元の再接続・再選択も確認する。
7. 一覧から外しても残したコピーと，写真の差替え後の旧コピーを容量画面から整理する。使用中素材・別プロジェクト・外部ファイル・完成品が意図せず消えないことを確認する。

iPhone 15への導入・実機確認はユーザーが後日対応としているため，今回はその再接続を要求しない。iPhone向けのコンパイル・シミュレーター確認は省略しない。
