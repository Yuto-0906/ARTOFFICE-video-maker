# iOS版の実機受入試験

この文書は実施手順と記録欄であり，実機試験の成功を示すものではない。実装・Codemagicの結果は[IOS_PROGRESS.md](IOS_PROGRESS.md)，要件は[IOS_IMPLEMENTATION_PLAN.md](IOS_IMPLEMENTATION_PLAN.md)を参照する。

2026年10月26日のユーザー指示により，5時間規模の実素材試験は今回の必須項目から外した。実機では短い素材を使う。長時間の時刻・区間・容量はモデル試験で確認し，5時間連続動作の性能は未測定と記録する。

## 対象と開始条件

| 項目 | iPhone | iPad |
|---|---|---|
| 対象 | iPhone 15。Apple Developerの登録モデル名を確認。本体のUSB照合・導入は27日のユーザー指示により後日対応 | iPad Pro 13-in (M4)。実機の`iPad16,5`と登録済み端末IDの一致を確認 |
| OS | 27.0.1との申告。導入時に確認する | 実機から27.0.1を読み戻した |
| 署名済みIPA・実機起動 | IPAは署名・構成検査済み。実機導入は未実施 | 2026年10月27日に導入成功。1.0（ビルド1），`ProfileValidated: true`。ユーザーが起動・イベント名の保存再開・1080p/30fps出力の映像・音声・名前を確認 |
| 5時間規模の実素材試験 | ユーザー指示により今回は実施しない | ユーザー指示により今回は実施しない |

Apple Developerへのログインと署名情報の照合後に，`ios-device`で開発用IPAを作成する。Codemagicへ新しくP12・パスワード・プロファイルを送る前に，対象データと送信先の承認を確認する。秘密情報や端末IDはこの記録へ記載しない。Windowsからの導入後は，Bundle ID・バージョン・プロファイルの検証状態と実際の起動を確認する。

2026年10月26日に，今回のApp ID・両端末用プロファイルの登録と，署名情報をARTOFFICE用のCodemagic Secretへ送信する承認を得た。アプリ専用プロファイルを生成し，既存のApple Development証明書・開発チーム・接続中のiPadとの一致まで検査済みである。IPAの作成・導入が成功したことを示す記録ではない。

26日にiPadへの導入をいったん保留し，27日にユーザーの指示で再開した。[署名ビルド #1](https://codemagic.io/app/6adb7fa259debc2d2f15db9f/build/6adf5daf4a72334e32e55b94)，ソース`b3dc4d9`のIPAを使い，接続中のM4 iPadとプロファイルを再照合して導入した。インストール終了コード0と，対象アプリの登録情報を読み戻した。起動と保存再開・書き出しの再生結果はユーザーの回答で確認した。107.5667秒の素材の新規出力は15.5419秒，観測した最大常駐メモリは約301MB，温度状態はnominalだった。区間再利用の別実行と区別した数値・条件は[IOS_PROGRESS.md](IOS_PROGRESS.md)に記録した。

その後，Core14件と署名ビルドを通した`f3aa9a8`へ上書き更新した。更新前後で編集JSONが一致し，ユーザーが同じプロジェクトの新規出力・再生も確認した。今回の診断は同時処理上限3，15.6236秒，最大約314MB，温度状態nominalだった。上限2の15.5419秒と速度はほぼ同じで，今回の素材での高速化は確認できなかった。

完成品の管理情報からも1920×1080・30fps・H.264・Rec.709，48kHzステレオAACを確認した。映像・音声・コンテナの記録上の長さはいずれも107.566667秒だった。動画本体を取得せず`ftyp`・`moov`のみをFFprobeで検査した結果であり，デコード後の全フレーム検査とは別である。

素材は外部へアップロードせず，ユーザー指定のライブ動画を端末または接続ストレージで使う。単一の長いファイルと，多数の分割ファイルの両方を含める。解像度・コーデック・HDRの有無・フレームレート・素材数・合計時間・容量を記録する。

## 今回実施する短い素材の試験

1. 短い素材で，取込み，並べ替え，前後カット，分割連結，日本語のバンド名，フェード，チャプター，写真の切抜きを確認する。
2. 編集を保存してアプリを終了し，再起動して開く。コピーした素材は取込み元に依存せず再開できることを確認する。参照素材はドライブの再接続・再選択も試す。
3. 1080pと1440p，29.97・30・59.94・60fpsの短い出力を確認する。回転付き素材，HDR→SDR，音声がない素材，44.1kHzなど48kHz以外の音声，VFRも含める。
4. 短い素材で，処理中の中止，バックグラウンド移行，アプリの終了後の再実行を確認する。確定済み区間の再利用と，変更条件の照合は，複数の短い区間を作る自動試験でも確認する。
5. 30fps系と60fps系，1080pと1440pを区別し，実施した素材条件と結果を両端末で記録する。実素材を合計5時間まで延ばす試験は任意とする。

長時間出力の前に，アプリの容量表示と実際の残容量を照合する。外部への直接出力も確認する。選択したファイルシステムが数十GBの単一ファイルを保存できることを確認し，4GBを超えるファイルを保存できない保存先は使わない。

保存先の上限を照会できる場合は，診断の`destinationMaximumFileBytes`へ記録する。FATの上限を超える容量の拒否は，5時間相当の容量モデルを使う自動試験でも確認する。未取得は制限なしの証明ではなく，クラウド・ファイル提供アプリの個別制限も確認する。開始時の見積りに収まっても，結合前の実サイズ確認で拒否された場合は，別の保存先を選んで処理済み区間から再実行する。

## 新規処理と再利用を分けて測る

速度を測る前には，必要な完成品を外部へ保存して再生を確認する。アプリ内の完成品だけを削除する操作と，処理済み区間を削除する操作は別に行える。編集情報と入力素材を残したまま，試験に必要な作業容量を確保する。

新規エンコードの計測では，対象プロジェクトの「処理済み区間を削除」を実行してから出力する。区間を再利用した実行は復旧性能として別に記録する。再利用の実行時間を，新規エンコードの速度として報告しない。

書き出し画面の「直近の診断レポートを共有」から`performance.json`を取得する。失敗・中止した場合も対象とし，完成品は完成品として確認できたものだけを扱う。

| 記録する値 | 読み方 |
|---|---|
| `systemVersion`・`budget`・`metalDevice` | 実行環境。シミュレーターの値は実機の証拠にしない |
| `resolution`・`frameRate`・`audioBitRate` | 実際に選んだ出力条件 |
| `status`・`startedAt` | 試行の状態と開始時刻。完成品の確定記録も併せて確認する |
| `elapsedSeconds` | 準備から最終化までの経過時間 |
| `finalizationSeconds` | 区間を完成ファイルにまとめる時間 |
| `chunks` | 今回処理した区間。再利用した区間を新規処理と数えない |
| `performanceWindows` | 1分ごとのメモリ最大値と温度状態 |
| `peakSampledResidentBytes` | 1秒間隔の測定で観測した最大値。瞬間的なピークの保証ではない |

RTFは「準備・最終化を含む経過秒数÷完成動画の再生秒数」で求める。1080p・SDRでRTF≦1へ近づける初期目標を，端末別・素材別に評価する。ハードウェアエンコーダーの使用は別に確認し，AVFoundationの採用やMetalのデバイス名だけで証明済みとしない。

CI待ちの追加ソースには，`lowPowerModeEnabled`と`memoryWarningCount`を`budget`・`performanceWindows`へ記録する処理もある。導入済みの`f3aa9a8`には含まれない。検証できた後の実機試験では，低電力モード切替時の出力条件の保持，警告後の同時処理数の抑制・再生成可能なキャッシュの解放を確認する。メモリ警告の試験で実機のメモリを意図的に使い切る必要はなく，通知を使う専用試験と区別する。

## 完成動画と復旧の確認

- 冒頭・各バンドの境界・各処理区間の前後・最後のバンド・末尾を再生し，映像の重複・欠落と音声の無音・重複・同期ずれを確認する。
- 縦動画の向き，縦横比，HDRからSDRへ変換した色，日本語タイトルの読める大きさ，サムネイルと画面内の切抜き位置を確認する。
- 書き出し画面の「仕上がりを確認」で，カット位置・タイトル・映像フェード・音声のつながりを完成動画と比較する。各バンドへの移動，末尾へのシーク，閉じてからの再表示，バックグラウンド移行後の停止を両端末で確認する。プレビューの解像度と完成動画の画質設定は分けて確認する。
- アプリの終了・端末再起動後に，編集内容と完成品を開き直す。未完了の試行は案内が表示され，再実行できることを確認する。
- 外付けストレージの切断・再接続と，容量不足時の挙動を確認する。編集情報・入力素材・正常な確定済み区間が失われないことを確認する。
- 完成品の整理では，アプリ内だけを削除し，外部へ保存したファイル・入力素材・編集情報・処理済み区間が残ることを確認する。
- バンド名を1か所訂正して再出力し，診断の`reusedChunkIndices`と新規エンコードした`chunks`を比較する。タイトルが表示される区間だけが作り直され，変更に関係しない区間が再利用されることを確認する。カット位置・素材・画質・フレームレートを変えた場合は，影響する区間を再生成する。再利用の計測結果は新規エンコードの速度と分ける。

実行したソースのコミット，署名ビルドのURL，素材構成，画質設定，充電状態，開始時の残容量，診断レポート，完成品の検査結果をセットで記録する。今回の短い試験の完了と，未実施の5時間連続動作の保証は分けて記録する。再導入は[IOS_INSTALL_WINDOWS.md](IOS_INSTALL_WINDOWS.md)を参照する。
