# iOS版の実機受入試験

この文書は実施手順と記録欄であり，実機試験の成功を示すものではない。実装・Codemagicの結果は[IOS_PROGRESS.md](IOS_PROGRESS.md)，要件は[IOS_IMPLEMENTATION_PLAN.md](IOS_IMPLEMENTATION_PLAN.md)を参照する。

## 対象と開始条件

| 項目 | iPhone | iPad |
|---|---|---|
| 対象 | iPhone 15 | ユーザー所有の13インチM4搭載機。Air／Proなどの正式名は実機から取得する |
| OS | 27.0.1との申告。導入時に確認する | 27.0.1との申告。導入時に確認する |
| 署名済みIPA・実機起動 | 未実施 | 未実施 |
| 5時間規模の出力 | 未実施 | 未実施 |

Apple Developerへのログインと署名情報の照合後に，`ios-device`で開発用IPAを作成する。Codemagicへ新しくP12・パスワード・プロファイルを送る前に，対象データと送信先の承認を確認する。秘密情報や端末IDはこの記録へ記載しない。Windowsからの導入後は，Bundle ID・バージョン・プロファイルの検証状態と実際の起動を確認する。

素材は外部へアップロードせず，ユーザー指定のライブ動画を端末または接続ストレージで使う。単一の長いファイルと，多数の分割ファイルの両方を含める。解像度・コーデック・HDRの有無・フレームレート・素材数・合計時間・容量を記録する。

## 短い試験から5時間まで

1. 短い素材で，取込み，並べ替え，前後カット，分割連結，日本語のバンド名，フェード，チャプター，写真の切抜きを確認する。
2. 編集を保存してアプリを終了し，再起動して開く。コピーした素材は取込み元に依存せず再開できることを確認する。参照素材はドライブの再接続・再選択も試す。
3. 1080pと1440p，29.97・30・59.94・60fpsの短い出力を確認する。回転付き素材，HDR→SDR，音声がない素材，44.1kHzなど48kHz以外の音声，VFRも含める。
4. 30分程度に延ばし，処理中の中止，バックグラウンド移行，アプリの終了，最終化中断からの再実行を確認する。完了済み区間が再利用されることと，変更した設定で古い区間が混在しないことを確認する。
5. 合計5時間規模の代表素材を使い，5時間前後の完成動画を両端末で出力する。30fps系と60fps系を分け，1440pも両端末で評価する。実際の素材に合う設定を使い，30fps素材の60fps化だけを60fps素材の性能として扱わない。

長時間出力の前に，アプリの容量表示と実際の残容量を照合する。外部への直接出力も確認する。選択したファイルシステムが数十GBの単一ファイルを保存できることを確認し，4GBを超えるファイルを保存できない保存先は使わない。

## 新規処理と再利用を分けて測る

速度を測る前には，必要な完成品を外部へ保存して再生を確認する。アプリ内の完成品だけを削除する操作と，処理済み区間を削除する操作は別に行える。編集情報と入力素材を残したまま，試験に必要な作業容量を確保する。

新規エンコードの計測では，対象プロジェクトの「処理済み区間を削除」を実行してから出力する。区間を再利用した実行は復旧性能として別に記録する。再利用の実行時間を，新規エンコードの速度として報告しない。

書き出し画面の「直近の診断レポートを共有」から`performance.json`を取得する。失敗・中止した場合も対象とし，完成品は完成品として確認できたものだけを扱う。

| 記録する値 | 読み方 |
|---|---|
| `systemVersion`・`budget`・`metalDevice` | 実行環境。シミュレーターの値は実機の証拠にしない |
| `resolution`・`frameRate`・`audioBitRate` | 実際に選んだ出力条件 |
| `status`・`startedAt` | 試行の状態と開始時刻。完成品の確定記録も併せて確認する |
| `elapsedSeconds` | 準備から最終化までの経過時間 |
| `finalizationSeconds` | 区間を完成ファイルにまとめる時間 |
| `chunks` | 今回処理した区間。再利用した区間を新規処理と数えない |
| `performanceWindows` | 1分ごとのメモリ最大値と温度状態 |
| `peakSampledResidentBytes` | 1秒間隔の測定で観測した最大値。瞬間的なピークの保証ではない |

RTFは「準備・最終化を含む経過秒数÷完成動画の再生秒数」で求める。1080p・SDRでRTF≦1へ近づける初期目標を，端末別・素材別に評価する。ハードウェアエンコーダーの使用は別に確認し，AVFoundationの採用やMetalのデバイス名だけで証明済みとしない。

## 完成動画と復旧の確認

- 冒頭・各バンドの境界・各処理区間の前後・最後のバンド・末尾を再生し，映像の重複・欠落と音声の無音・重複・同期ずれを確認する。
- 縦動画の向き，縦横比，HDRからSDRへ変換した色，日本語タイトルの読める大きさ，サムネイルと画面内の切抜き位置を確認する。
- アプリの終了・端末再起動後に，編集内容と完成品を開き直す。未完了の試行は案内が表示され，再実行できることを確認する。
- 外付けストレージの切断・再接続と，容量不足時の挙動を確認する。編集情報・入力素材・正常な確定済み区間が失われないことを確認する。
- 完成品の整理では，アプリ内だけを削除し，外部へ保存したファイル・入力素材・編集情報・処理済み区間が残ることを確認する。

実行したソースのコミット，署名ビルドのURL，素材構成，画質設定，充電状態，開始時の残容量，診断レポート，完成品の検査結果をセットで記録する。未確認の項目を残したまま，両端末の5時間処理を完了・最適化済みとは判定しない。
